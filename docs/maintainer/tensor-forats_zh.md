# NInfer 持久化张量数值格式

本文档定义当前 `.ninfer` 工件接受的九种持久化张量数值格式：它们的逻辑字、量化语义、适用时的规范参考编码器以及一致性边界。[容器封装](artifact-container.md)、[物理布局](storage-layouts.md)、权重配方和运行时状态编解码器分别定义。

## 1. 已注册格式

NInfer 在四个类别中恰好有九种持久化张量数值格式。

直接标量格式为每个张量元素保留一个逻辑标量字：

| 规范名称 | 类别 | 逻辑宽度 | 逻辑含义 |
|---|---|---:|---|
| `bf16` | 直接浮点 | 16 | bfloat16 位编码 |
| `fp32` | 直接浮点 | 32 | IEEE-754 binary32 |
| `int32` | 直接有符号整数 | 32 | 32 位二进制补码整数 |

分组量化权重格式保留有符号码，以及每个逻辑组一个 scale：

| 规范名称 | 码宽 | 组大小 | 合法有符号码 | Scale | 完整组每权重逻辑位数 |
|---|---:|---:|---:|---|---:|
| `q4_g64_fp16` | 4 | 64 | `[-8, 7]` | 每组一个 binary16 scale | 4.25 |
| `q5_g64_fp16` | 5 | 64 | `[-16, 15]` | 每组一个 binary16 scale | 5.25 |
| `q6_g64_fp16` | 6 | 64 | `[-32, 31]` | 每组一个 binary16 scale | 6.25 |
| `q8_g32_fp16` | 8 | 32 | `[-127, 127]` | 每组一个 binary16 scale | 8.50 |

块缩放浮点权重格式为：

| 规范名称 | 码 | K 组 | 块 scale | 全局字段 |
|---|---|---:|---|---|
| `nvfp4` | E2M1，每权重 4 位 | 16 | 每组一个 E4M3FN 字 | 一个正 FP32 weight divisor |

行缩放浮点权重格式为：

| 规范名称 | 码 | Scale 粒度 | Scale |
|---|---|---|---|
| `fp8_e4m3fn_row_bf16` | E4M3FN，每权重 8 位 | 每个逻辑行一个乘数 | BF16 |

每个名称都固定了码和 scale 契约。格式注册表实现在 [`tools/artifact/formats.py`](../../tools/artifact/formats.py) 和 [`src/artifact/formats.cpp`](../../src/artifact/formats.cpp) 中。增加格式需要明确的数值定义和编解码器实现。布局支持与 Op 支持相互独立：已知格式可以被存储，即使并非每个模型消费者都支持它。

## 2. 术语和所有权

注册表将以下关注点分开。

### 2.1 持久化数值格式

**持久化数值格式**定义从工件恢复数值张量所需的逻辑字。封闭注册表包含直接标量格式、分组有符号整数格式、块缩放 `nvfp4` 格式以及行缩放 `fp8_e4m3fn_row_bf16` 格式。它不标识张量的模型角色、物理字节布局或支持的消费者。

### 2.2 直接标量格式

**直接标量格式**为每个逻辑张量坐标分配一个固定宽度的逻辑字。它定义该字的值，不需要组、scale、zero point 或重建步骤。`bf16`、`fp32` 和 `int32` 是直接标量格式。

“直接”不要求特定的物理布局，也不禁止已注册的无损存储变换。它只表示布局解码恢复的是原始逻辑字，而不是另一个字的量化近似。

### 2.3 量化方案

**量化方案**只定义量化权重的持久化逻辑表示：

- 码域；
- 分组轴和组大小；
- scale 类型和 scale 粒度；
- 码和 scale 的有效性规则；
- 每个表示权重的数学重建方式。

上面的六个量化名称在此意义下标识方案。它们的含义不可变：消费者不得根据上下文推断不同的 zero point、scale 几何、码范围或重建规则。

### 2.4 转换方法

**转换方法**从逻辑源产生所选格式的字。Scale 选择、舍入顺序、校准、裁剪和误差优化都属于此处。方法可以保留已经编码的源，也可以量化浮点值。

内置的 `grouped_absmax` 方法为四种分组整数格式实现第 7 节的参考编码器。`fp8_row_maxabs` 将源值舍入为 BF16，并以 BF16 乘数将每行量化为 E4M3FN 码。`import_encoded` 保留兼容的 FP8 或 NVFP4 码、scale，以及 NVFP4 的矩阵 weight divisor。NInfer 当前没有内置的浮点到 NVFP4 量化器。

配方可以提供 Python 可调用对象作为方法。不同方法可以为同一格式产生不同的合法码和 scale；它们共享该格式的解码契约。方法标识和数值参数属于转换来源信息。

直接格式同样将表示与转换分开。例如，`bf16` 定义存储位；转换方法决定 FP32 源如何变成这些位。

### 2.5 权重配方

**权重配方**为每个逻辑参数或区域选择格式和转换方法。参数含义和形状来自架构。源选择、分组和每个输入的激活权限见[转换指南](../weight-conversion.md)。

### 2.6 存储布局

**存储布局**将直接逻辑字或量化码与 scale 映射为字节。它负责的内容包括：

- 位和字节打包；
- 平面顺序和交错；
- 行、tile、expert 或内核原生顺序；
- 物理填充和对齐；
- 字节序以及布局特定的验证元数据。

一个格式可以有多个经过明确支持的布局，但每个布局都必须解码为完全相同的直接字或逻辑码和 scale。当前注册的布局是：直接字使用 `contiguous_le_v1`，分组有符号整数格式使用 `row_split_k128_v1`，`nvfp4` 使用 `block_scale_k16_m128x4_v1`，`fp8_e4m3fn_row_bf16` 使用 `row_scale_v1`。字节序、平面打包、填充、swizzle、divisor 放置和对齐规则属于布局注册表，而非这九种数值格式。

### 2.7 计算配置和内核支持

**计算配置**负责可观察的输入和输出类型、明确的语义转换或量化边界、确定性要求以及算子级数值容差。内核操作数和累加精度、分块、Tensor Core 使用、内部归约树、私有暂存或物化、切分策略、融合调度、启动几何和硬件分派仍是实现选择。精确或逐位操作可能要求精确的可观察结果；这不会将浮点 oracle 变成规定内部求值顺序的工具。

在 `q8_g32_fp16` 中，`fp16` 后缀描述存储的 scale。激活和输出精度由消费者选择。内核支持数值格式、存储布局、算子语义、形状、计算配置和执行平台的特定组合。

原生 Op 实现定义这些组合，并在准备或消费操作数时检查它们。配方能够编码某种组合，与原生执行是否支持该组合相互独立。

### 2.8 运行时状态编解码器

KV-cache 量化、激活量化、临时内核压缩、循环状态和通信格式都是运行时状态编解码器。即使它们也使用有符号整数和分组 scale，它们仍在此持久化张量注册表之外。特别是，INT8 KV-cache 格式不能仅因为某些字段看起来相似，就标记为 `q8_g32_fp16`。

## 3. 规范标识和格式语义

### 3.1 直接标量格式

#### `bf16`

`bf16` 是 bfloat16 位编码。其抽象的 16 位字在第 15 位有一个符号位，在第 14 至 7 位有一个带偏置 127 的 8 位指数，在第 6 至 0 位有一个 7 位尾数小数。

其值类别为：

- 指数为零且小数为零：根据符号位确定正零或负零；
- 指数为零且小数非零：非规格化值 `(-1)^sign * fraction * 2^-133`；
- 指数为 1 至 254：正规值 `(-1)^sign * 2^(exponent-127) * (1 + fraction/2^7)`；
- 指数为 255 且小数为零：正无穷或负无穷；
- 指数为 255 且小数非零：NaN，包括其符号、quiet/signaling 位和负载。

等价地，精确扩展到 binary32 时，将 16 位逻辑字放入 binary32 字的高 16 位，并追加 16 个低零位。`bf16` 不是 IEEE binary16/FP16。

格式层面所有 65,536 个逻辑 BF16 字都有效。正零和负零仍是不同的字。无穷和 NaN 同样可表示，直接布局必须恢复原始逻辑字，不能规范化 NaN 负载或改变其 quiet/signaling 位。某个模型张量是否允许非有限值属于参数或转换约束，而不是另一种 BF16 格式。除非计算配置如此规定，否则计算操作不要求保留 NaN 负载。

#### `fp32`

`fp32` 是 IEEE-754 binary32：第 31 位为符号位，第 30 至 23 位为带偏置 127 的 8 位指数，第 22 至 0 位为 23 位尾数小数。其零、非规格化数、正规值、无穷和 NaN 遵循标准 binary32 解释；最小正非规格化值为 `2^-149`。

格式层面所有 `2^32` 个逻辑字都有效。与 BF16 一样，带符号的零、无穷和 NaN 负载仍是不同的持久化字。对非有限值的张量特定限制属于配方，而计算时的传播属于计算配置。

#### `int32`

`int32` 是 32 位二进制补码有符号整数。对于抽象的无符号逻辑字 `u`：

```text
value = u                         if u < 2^31
value = u - 2^32                  otherwise
```

每个 32 位字都有效，值范围为 `[-2147483648, 2147483647]`。`int32` 没有 scale、zero point、饱和行为、哨兵约定，也不依赖主机 C++ 的 `int` 类型。非负性、词表边界或 `-1` 的含义等要求属于具体张量角色。

#### 直接格式的通用规则

对于直接张量，所选格式的每个逻辑坐标拥有一个独立字。直接格式与形状无关：rank、维度有效性、坐标遍历、步长、填充和对齐由容器及所选布局定义，而不是由标量格式定义。字节序同样是布局属性，绝不能从主机原生表示推断。

同一源类型的持久化在逻辑字边界上是逐位一致的。不同源类型和目标类型之间的转换不会隐式发生。配方必须定义这种转换，包括 FP32 到 BF16 的舍入以及 INT32 的值转换和范围策略。

控制参数、普通权重、归一化参数、索引和映射使用直接格式，并另有独立的逻辑参数角色。

### 3.2 分组有符号整数权重标识

这些标识记录码宽、组大小和 scale 类型。例如，`q4_g64_fp16` 使用 4 位有符号码，每 64 个权重一组，并为每组使用一个 IEEE-754 binary16 scale。`q5_g64_fp16`、`q6_g64_fp16` 和 `q8_g32_fp16` 遵循相同的命名约定。

解析器通过格式注册表解析名称。`Q4`、`Q5`、`Q6` 和 `Q8` 是正文缩写；工件存储完整的规范名称。

### 3.3 `nvfp4`

`nvfp4` 是块缩放浮点权重表示，不是有符号整数 `QuantFormat`。对于逻辑矩阵 `[N,K]`，每个 K 轴组包含 16 个 E2M1 码字和一个 E4M3FN scale 字。该表示还包含一个针对完整矩阵的 FP32 序列化 weight divisor `d_w`。

E2M1 字的第 3 位是符号位，第 2:1 位是指数，第 0 位是尾数。正码字 `0..7` 解码为：

```text
0.0, 0.5, 1.0, 1.5, 2.0, 3.0, 4.0, 6.0
```

位 3 会对该值取负。字 `0x0` 和 `0x8` 是不同的正零和负零字；全部 16 个码字都有效，并且必须逐位保留。

E4M3FN 字的第 7 位是符号位，位 6:3 为指数 `e`，位 2:0 为小数 `m`，偏置为 7：

```text
e == 0, m == 0 : signed zero
e == 0, m != 0 : (-1)^sign * m * 2^-9
1 <= e <= 14   : (-1)^sign * (1 + m/8) * 2^(e-7)
e == 15, m < 7 : (-1)^sign * (1 + m/8) * 2^8
e == 15, m == 7: NaN
```

存储的 NVFP4 权重 scale 只接受符号位为零的有限字，包括正零。负值、负零和两个 NaN 字均无效。序列化的 binary32 字 `d_w` 必须是有限且严格为正。

对于码 `c[n,k]`、scale 字 `s[n,g]` 和 `g=floor(k/16)`，精确表示的权重为：

```text
W[n,k] = decode_e2m1(c[n,k]) * decode_e4m3fn(s[n,g]) / d_w
```

`import_encoded` 原样复制这三个字段，不重新量化或规范化。激活校准不属于此权重格式。特别是，NVFP4 执行路径使用的站点级输入 divisor 是独立的模型角色张量，不能从 `nvfp4`、其块 scale 或 `d_w` 推断出来。

### 3.4 `fp8_e4m3fn_row_bf16`

`fp8_e4m3fn_row_bf16` 是具有正维度的 rank-two 权重矩阵 `[N,K]`。每个逻辑权重拥有一个 E4M3FN 码字，每个逻辑行拥有一个 BF16 反量化乘数。行是矩阵的第一个坐标 `n`；“行”是结构属性，不推断模型特定的通道角色。

E4M3FN 码的含义见第 3.3 节。两个带符号的零字以及每个有限的非规格化或正规字都有效。正 NaN 和负 NaN 字 `0x7f` 与 `0xff` 无效；E4M3FN 没有无穷字。

BF16 scale 的含义见第 3.1 节。有效的行 scale 符号位为零且为有限值，包括正零和正非规格化数。负值、负零、无穷和 NaN 无效。如果行 scale 是正零，则该行的每个码必须是正零 `0x00` 或负零 `0x80`。反之不要求成立。

对于码字 `c[n,k]` 和行 scale 字 `s[n]`，精确表示的权重为：

```text
c32          = exact_e4m3fn_to_binary32(c[n,k])
s32          = exact_bfloat16_to_binary32(s[n])
w_hat[n,k]   = binary32(c32 * s32)
```

Scale 是乘数。除以 `s[n]`、使用 zero point、矩阵级 divisor 或其他隐含系数，都实现了不同的格式。码平面和行 scale 平面共同组成一个持久化权重；单独的 E4M3FN 张量或独立命名的 scale 张量都不是此格式的别名。

该格式不定义如何为浮点源分配 scale 或舍入为 E4M3FN。配方要么精确保留已经选定的码和 scale 字，要么指定其转换方法。激活量化和激活 scale 属于独立的计算或运行时状态关注点，不是此格式的持久化字段。

## 4. 分组有符号整数张量模型

### 4.1 形状和分组轴

对于四种分组有符号整数方案，令逻辑量化权重张量的 rank 为 `r >= 1`，正的 `K`，形状为：

```text
[D0, D1, ..., D(r-2), K]
```

当 `r = 1` 时，该记法简化为没有前导坐标的 `[K]`。

最后一维 `K` 始终是量化轴。前导维度中的每个坐标标识一个独立的逻辑行。对于前导坐标向量 `p` 和元素索引 `k`：

```text
group(p, k) = (p, floor(k / G))
```

其中 Q4/Q5/Q6 的 `G` 为 64，Q8 的 `G` 为 32。组不会跨越行边界或任何前导维度。例如，对于 rank-3 expert bank `[E, N, K]`，每个 `(expert, row)` 对独立量化；组不能从一个 expert 跨到另一个 expert。

因此逻辑 scale 张量的形状为：

```text
[D0, D1, ..., D(r-2), ceil_div(K, G)]
```

此定义不为前导维度赋予输出通道、expert、adapter 或卷积轴等含义。检查点适配器负责在编码前执行将目标量化轴放到最后所需的 reshape 或转置。这是抽象的方案定义。当前实现的 `row_split_k128_v1` 布局和规范生产器只接受正的 rank-two 矩阵 `[N,K]`；支持更高阶的物理张量需要显式注册并实现的布局，或定义保持语义的 rank-two reshape 的模型配方。

### 4.2 最后的不完整组

在方案层面，`K` 不必能被 `G` 整除。当结果非零时，每行的最后一组包含 `K - floor(K / G) * G` 个逻辑值。它的 scale 和码只根据这些逻辑值计算。

存储布局可以物理扩展该组或进一步填充张量，但必须满足以下全部条件：

- 填充不属于逻辑张量形状；
- 填充不得改变任何逻辑 scale 或码；
- 填充不得改变任何解码后的逻辑值或可观察算子结果；
- 读取器从工件契约获取逻辑和物理范围，绝不能根据负载长度猜测。

方案不选择填充后的范围、对齐倍数、是否存储填充或物化填充的规范内容。这些事项由每个存储布局定义，并在各自边界验证。逻辑编码器不产生物理填充。

## 5. 分组有符号整数码域

四种方案都是无 zero point、仅权重的有符号整数方案。本文档中的“对称”表示重建为 `scale * signed_code` 且 zero point 为零；它不表示每个合法区间的正负幅度相等。

### 5.1 Q4、Q5 和 Q6

逻辑码是指定宽度的二进制补码有符号整数：

| 方案 | 宽度 | 符号位 | 合法码区间 | 参考编码器使用的 `qmax` |
|---|---:|---:|---:|---:|
| `q4_g64_fp16` | 4 | `0x8` | `[-8, 7]` | 7 |
| `q5_g64_fp16` | 5 | `0x10` | `[-16, 15]` | 15 |
| `q6_g64_fp16` | 6 | `0x20` | `[-32, 31]` | 31 |

指定逻辑宽度的每个位模式都有效。无符号逻辑字 `u` 与有符号码 `q` 的转换为：

```text
q = u                         if u < 2^(b - 1)
q = u - 2^b                   otherwise
```

这不是偏移二进制、符号-幅值编码、码本索引或无符号 GPTQ/AWQ zero point 约定。存储布局可以拆分或重排位，但布局解码后的逻辑字和有符号值必须恰好是此处定义的值。

### 5.2 Q8

`q8_g32_fp16` 使用 8 位二进制补码有符号码，且有意限制在 `[-127, 127]`。字节模式 `0x80` 本应表示 `-128`，但在合法工件语言之外。项目自有量化器绝不能产生它；解码语义只为合法码流定义。

该限制属于方案，而不是编码器偏好。内核可以使用原生有符号字节加载，因为已注册的转换路径建立了该码不变量；这种实现便利不使 `-128` 合法。受信任的本地运行时不会仅为证明生产器已经建立的不变量，而重新扫描完整 Q8 负载。

## 6. 分组有符号整数 scale 和重建语义

### 6.1 Scale 表示

每个逻辑组恰好有一个 IEEE-754 binary16 scale。它是反量化乘数，而不是 inverse scale。没有 zero point、偏移、最小值、secondary scale、块指数或码本。

有效 scale 为以下之一：

- 正零，binary16 位模式 `0x0000`；
- 有限的正 binary16 正规数或非规格化数。

负有限值、负零、正或负无穷以及任何 NaN 均无效。正 binary16 非规格化数有效；消费者必须保留其定义值。特别是，最小正 binary16 scale 为 `2^-24`，位模式为 `0x0001`。

如果存储的 scale 是正零，则该组的每个逻辑码都必须为零。反之不要求成立：合法表示可以有正 scale 和全零码。但规范参考编码器对全零源组仍会输出唯一的 `scale = +0, codes = 0` 表示。

### 6.2 抽象重建

令 `q[p, k]` 为有符号码，`s[p, g]` 为组 `g` 的 binary16 scale。表示的权重为：

```text
g         = floor(k / G)
s32       = exact_binary16_to_binary32(s[p, g])
w_hat[p,k] = binary32(s32 * binary32(q[p, k]))
```

该 binary32 表达式是数学一致性 oracle。每个合法有符号码都能在 binary32 中精确表示，每个 binary16 值都能精确扩展到 binary32，其乘积就是方案表示的值。内核不必物化该乘积，也不必在每个阶段使用 binary32；其算子级结果依据该实现配置中 Op 命名的标准，与此 oracle 对比进行验证。

公式 `code / scale` 是错误的：存储的 scale 是乘数。引入 zero point、将码区间重新居中或通过 BF16 转换 scale 的独立方案解码器或精确 oracle，实现的是不同的数值契约。生产内核可以使用较低精度的内部暂存、不同的累加精度或另一种归约结合方式；这些属于实现选择，可观察的算子结果必须以相同 oracle 通过 Op 命名标准的检验。

### 6.3 逻辑存储成本

对于码宽 `b`、组大小 `G` 和每组一个 16 位 scale，完整组的理想逻辑成本为：

```text
logical_bits_per_weight = b + 16 / G
```

这给出第 1 节中的值。它不包括不完整组开销、张量元数据、物理填充、对齐、索引、完整性数据以及布局特定的重复。不得将它引用为精确的 `.ninfer` 工件大小。

16 位 scale 在 G32 时每个权重贡献 0.5 位，在 G64 时贡献 0.25 位。模型参数使用哪种格式由其配方决定。

## 7. 分组有符号整数参考编码器

### 7.1 目的和输入边界

内置的 `grouped_absmax` 方法使用每行每组的绝对值最大值。其实现位于 [`groupwise.py`](../../tools/convert/quantization/groupwise.py)。下面的算术定义其精确输出，包括 FP16 scale 舍入和倒数乘法码选择。它适用于四种分组整数格式。

实现接受正的 rank-two 矩阵，拒绝非有限源值和不可表示的 scale，并为 `row_split_k128_v1` 提供零尾部填充。

逻辑源提供第 4 节形状和轴约定中的值。每个源值在分组处理之前使用舍入到最近、平局取偶数转换为 IEEE-754 binary32。有限 BF16 和 binary16 值可精确转换；有限 binary32 值保持不变。如果源值无法表示为有限 binary32，编码器失败。

下面的所有 binary32 和 binary16 操作都使用舍入到最近、平局取偶数。如果会改变指定的 binary16 scale，则不允许 flush-to-zero。此有序算法的独立实现是编码器 oracle；第 9 节说明相关一致性证据。

### 7.2 每组算法

对于一个由有限 binary32 值 `x[i]` 组成的逻辑组，令 `(qmin, qmax)` 为所选方案的区间。规范结果为：

```text
amax = max_i(abs(x[i]))                         # binary32 values

if amax == +0:
    scale16 = binary16(+0)
    code[i] = 0 for every i
else:
    raw_scale32 = round_f32(amax / binary32(qmax))
    scale16     = round_f16(raw_scale32)

    if scale16 == +0:
        scale16 = binary16_from_bits(0x0001)    # 2^-24 underflow rescue

    if scale16 is not finite and positive:
        fail

    scale32 = exact_binary16_to_binary32(scale16)
    inv32   = round_f32(binary32(1.0) / scale32)

    for every i:
        normalized32 = round_f32(x[i] * inv32)
        rounded       = round_to_integral_ties_to_even(normalized32)
        code[i]       = clamp(rounded, qmin, qmax)
```

分母使用 `qmax`，而不是 `abs(qmin)`。因此 Q4 使用 7，Q5 使用 15，Q6 使用 31，Q8 使用 127。裁剪发生在整数舍入之后，所以 Q8 结果绝不会产生 `-128`。

整数舍入示例为：

```text
+0.5 ->  0       -0.5 ->  0
+1.5 ->  2       -1.5 -> -2
+2.5 ->  2       -2.5 -> -2
```

序列 `inv32 = round_f32(1 / scale32)` 后接 `normalized32 = round_f32(x * inv32)` 是此编码器的规范要求。将其替换为 `round_f32(x / scale32)` 即使实数表达式代数等价，也可能选择不同的整数码。

如果 `raw_scale32` 转换为 binary16 产生无穷，编码失败，而不是存储它或静默裁剪 scale。如果非零 `raw_scale32` 舍入为 binary16 零，则显式的 `0x0001` rescue 保留正的反量化 scale。全零组在倒数计算前处理，并始终产生正零 scale 和零码。

### 7.3 其他编码器

方案标识由持久化表示和重建契约决定，而不是由转换器寻找码的方式决定。只要所有输出码和 scale 满足第 4 至第 6 节，记录在案的上游、校准或误差优化编码器就可以产生相同的四种方案。

用户配方显式选择这些方法并记录其来源信息。其他方法不必逐位匹配 `grouped_absmax`，但必须产生所选格式的合法字。改变组几何、scale 类型、码域或重建方程，就需要另一种数值格式，以及它自己的编解码器和消费者支持。

## 8. 一致性职责

### 8.1 生产器和编码器

符合要求的生产器必须：

- 只产生已注册的数值格式；
- 未请求源类型转换时，精确保留每个直接逻辑字；
- 只应用配方明确规定的源类型转换；
- 对量化格式，保留逻辑形状和最后一轴分组规则；
- 对分组有符号整数格式，每个逻辑组产生一个有效 binary16 scale 和仅合法的有符号码，包括绝不产生 Q8 `-128`；
- 对 `nvfp4`，只产生有效的 E2M1 码字、非负有限 E4M3FN scale 字，以及符合第 3.3 节的有限正 FP32 weight divisor；
- 对 `fp8_e4m3fn_row_bf16`，只产生有限 E4M3FN 码字和有效 BF16 行乘数，并遵循第 3.4 节：正零 scale 行中只有带符号的零码合法；
- 记录足够的转换来源信息，让工件生产器能够识别值的派生方式；
- 当编码器转换浮点源值时，遇到非有限源数据或不可表示的 scale 必须失败，而不是静默量化或产生不可表示的 scale。

直接 BF16 和 FP32 格式可以表示非有限字，因此仅仅出现此类字并不自动构成生产器错误。某个张量是否允许这样的字属于参数或转换约束。物理填充由所选存储布局产生并验证，而不是由逻辑直接编码器或量化编码器产生。

只有声称规范参考一致性的分组有符号整数编码器才必须逐位重现第 7 节。其他配方可以为任何量化方案选择不同的合法字，但不能改变这些字已注册的含义。

### 8.2 容器和布局

`.ninfer` 容器和每个已注册存储布局必须：

- 明确标识数值格式；
- 将逻辑形状与任何物理填充范围分开保存；
- 精确重建每个直接逻辑字；
- 对分组有符号整数格式，明确逻辑组的数量和归属，并且无需从内核实现推断即可重建每个有符号码和 binary16 scale；
- 对 `nvfp4`，按照第 3.3 节重建每个 E2M1 码字、自然的 E4M3FN scale 字以及矩阵 FP32 divisor；
- 对 `fp8_e4m3fn_row_bf16`，按照第 3.4 节重建每个 E4M3FN 码字及其所属 BF16 行乘数；
- 如果物化填充，则定义其规范物理填充内容和生产器职责；
- 拒绝未知格式以及不支持的格式/布局组合；
- 定义定位和解码负载所需的结构检查。

容器不得嵌入开放式的 `(bits, group_size, scale_dtype)` 构造器，使未注册组合变得合法。其表示必须解析为一个封闭的规范标识；该表示属于容器契约。

### 8.3 读取器、加载器和绑定器

生产器建立上述数值不变量。布局编解码器保留选定的字并提供规范物理填充。通用读取器验证目录结构和负载边界；选定对象后，它解析对象的格式/布局，并检查编码几何和大小。未使用的可选组件不要求解码其权重。

语义绑定器检查参数角色、形状、视图和 Uses。必要时，它读取索引和激活 divisor 等便宜的角色特定值。原生 Op 准备、资源查询、预热或执行检查实际的操作数支持。不存在单独的全模型能力注册表。

运行时上传已编码负载并保留其物理表示。它不会在上传前扫描每个码、scale 或填充字节。编解码器和 Op 测试分别保护生产器契约和表示的值。

### 8.4 内核和算子

消费者内核或模型组件必须按照第 3.1 节解释直接逻辑字，按照第 3.2 节及第 5、6 节解释分组有符号整数标识、码和 scale，按照第 3.3 节解释 `nvfp4` 字和 divisor，并按照第 3.4 节解释行缩放 FP8 字。它可以选择私有融合、归约、暂存和中间精度；可观察 Op 结果依据该实现配置中 Op 命名的标准，与独立 oracle 对比验证。内核实现细节不改变持久化格式，也不能成为独立解码工件的必要条件。

不支持的原生组合在其消费者处失败。加载不会重新打包或重新量化权重来获得另一条执行路径。

## 9. 一致性证据

本文档的实现通过表示边界保护，而不是通过扫描枚举拼写或私有内核布局的测试保护。保留的编解码器和编码器证据包括：

- BF16、FP32 和 I32 字的精确代表性往返，包括带符号零、非规格化数、NaN 负载位和整数极值，以及拒绝隐式跨类型编码；
- Q4、Q5、Q6 和 Q8 的平面位顺序、合法区间端点、编码大小几何、部分 K 的零填充、连续行视图和任意行收集；
- 全部 16 个 E2M1 字、全部 256 个 E4M3FN 字、NVFP4 scale/divisor 有效性、精确的 divisor 重建方程以及已知的块 scale swizzle 偏移；
- 有限 E4M3FN 权重码有效性、BF16 行 scale 有效性、带符号零行、精确的码/scale 平面往返以及 `fp8_e4m3fn_row_bf16` 的行乘数重建方程；
- 规范 binary16 scale 舍入、使用倒数乘法而不是直接除法、正负平局取偶数、最小非规格化数 rescue，以及拒绝非有限或溢出的源组；
- 对部分填充组进行规范量化，随后精确解码已存储的码/scale。

对于直接格式，独立解码 oracle 是第 3.1 节中的抽象逻辑字。对于分组有符号整数格式，它是第 6.2 节中的 binary32 重建。其规范编码 oracle 是对第 7 节有序算法的逐位主机/软件实现；声称该配置的生产转换器必须与它一致，而不是用自身算术定义 oracle。`nvfp4` 解码 oracle 是第 3.3 节的 E2M1/E4M3FN/FP32 divisor 重建；当前生产器通过精确源字比较保护，而不是通过第 7 节保护。NVFP4 Op oracle 从表示的公共激活和这一精确解码的持久化权重开始。站点级激活 divisor 以及任何私有激活量化不会改变理想 Op 公式；其数值影响由生产路径的输出标准覆盖，而不是在 oracle 中复现。数值算子测试单独保护注册目标使用的组合，包括公共输入/输出格式、输出容差和真实目标形状。`fp8_e4m3fn_row_bf16` 解码 oracle 是第 3.4 节的 E4M3FN/BF16 行乘数重建；复制上游量化张量的生产器通过精确源字比较保护，而任何源到 FP8 的编码器都依据其命名配置保护。私有激活量化、暂存和累加仍是实现选择。
